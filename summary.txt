FILE AND CLASS EXPLANATION
==================================================

Below is a breakdown of every core file and class in the project, explaining what they do and how they fit into the overall architecture.

--------------------------------------------------
1. Core Data Models (The Building Blocks)
--------------------------------------------------
These files define the basic objects that the system manages.

- User.h / User.cpp
  * Class: `User`
  * Role: This is an abstract base class. It holds the core authentication data (`username`, `password`, `role`) common to everyone in the system. Because it has a pure virtual function (`display()`), you cannot create a raw User; you must create a specific subclass (Admin, Instructor, or Student).

- Admin.h / Admin.cpp
  * Class: `Admin` (inherits from `User`)
  * Role: A specialized user with the "ADMIN" role. Used for top-level system access.

- Instructor.h / Instructor.cpp
  * Class: `Instructor` (inherits from `User`)
  * Role: Adds specific fields for staff, such as `id`, `name`, and `departmentCode`.

- Student.h / Student.cpp
  * Class: `Student` (inherits from `User`)
  * Role: Adds detailed academic fields, such as `id`, `name`, `gpa`, `year`, `phone`, and `departmentCode`.

- Course.h / Course.cpp
  * Class: `Course`
  * Role: Represents an academic class (e.g., CS101). It stores the `capacity`, `creditHours`, and importantly, a vector of `enrolledStudents` (storing student IDs). It contains basic logic to prevent enrolling if the course is at max capacity.

- Department.h / Department.cpp
  * Class: `Department`
  * Role: A simple data structure holding the department `code` (e.g., "CS") and full `name` (e.g., "Computer Science").

--------------------------------------------------
2. Advanced Data Structures & Algorithms
--------------------------------------------------
These files handle complex calculations, sorting, and relationships between data.

- PrerequisiteGraph.h / PrerequisiteGraph.cpp
  * Class: `PrerequisiteGraph`
  * Role: Implements a Directed Graph using an adjacency list (an unordered_map). It models which courses are required to take other courses. 
  * Key Algorithms: Uses Breadth-First Search (BFS) to find and list all prerequisites for a specific course, and Depth-First Search (DFS) to detect cycles (ensuring a course doesn't accidentally require itself).

- SortStrategies.h
  * Classes: `BubbleSortStrategy`, `MergeSortStrategy`, `SelectionSortStrategy`
  * Role: Implements the "Strategy Design Pattern" for sorting. By isolating sorting algorithms into their own classes, the system is cleaner and easier to maintain.
  * Bubble Sort: Used for sorting Courses.
  * Merge Sort: Used for sorting Departments alphabetically (fast O(n log n) time).
  * Selection Sort: Used for sorting Students by GPA.

--------------------------------------------------
3. The Backend Controller
--------------------------------------------------
This file bridges the gap between the raw data and the user interface.

- CollegeSystem.h / CollegeSystem.cpp
  * Class: `CollegeSystem`
  * Role: This is the central "brain" of the application. It holds all the vectors (lists) of the actual data (`vector<Student>`, `vector<Course>`, etc.) and the `PrerequisiteGraph`.
  * Key Responsibilities:
    - Business Logic: Contains the `enrollStudentInCourse()` function, which calculates a student's total credit hours and blocks them from enrolling if it exceeds their GPA-based limit (e.g., GPA < 2.0 = 12 credits max).
    - Search: Implements Binary Search to quickly find Students by ID or Departments by name.
    - Initialization: Contains `initializeData()`, which generates all the mock users and courses when the program starts.

--------------------------------------------------
4. The Graphical User Interface (GUI)
--------------------------------------------------
These files render the application on the screen.

- MainWindow.h / MainWindow.cpp
  * Class: `MainWindow` (inherits from `QMainWindow`)
  * Role: Handles everything the user sees and clicks in the Qt6 application.
  * Key Responsibilities:
    - Session Management: Contains `showLoginDialog()` to authenticate users, and `onLogout()` to safely destroy and rebuild the UI.
    - Role-Based UI: Checks `currentRole` to decide whether to render the "Users" tab or hide the "Add User" button.
    - Dynamic Forms: Contains the logic for the "Add User" dialog, dynamically hiding and showing input fields (like GPA) based on whether an Admin is creating a Student, Instructor, or Admin.
    - Event Handling: Connects button clicks (Slots) to backend `CollegeSystem` functions (e.g., clicking the sort button triggers the Strategy Pattern sorts).

--------------------------------------------------
5. Application Entry Points
--------------------------------------------------
These files contain the standard `int main()` functions required to start a C++ program.

- main.cpp
  * Role: The entry point for the terminal-only (console) version of the application. Used for testing the backend logic without rendering graphics.

- gui_main.cpp
  * Role: The entry point for the Qt6 GUI application. It creates the `QApplication` instance, instantiates the `MainWindow`, and starts the main event loop (`app.exec()`), keeping the window open until the user exits.
